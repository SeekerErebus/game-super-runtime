# Original user assignment — 2026-10-15

This directory has been prepared with a basic supporting setup for your development work. You may replace any of them if necessary so long as it better supports your operation.
Build `game-super-runtime`. Game Super Runtime is an as yet non-existent game deployment tool for linux gaming, which enables extensive options for how every possible element of a linux game might be expected to start up via the use of yaml files. The standard convention for running is `game-super-runtime <APP-ID>` when from a desktop shortcut or from cli, or `game-super-runtime <APP-ID> %command%` when through the launch options of a Steam game. `<APP-ID>` will default to the app number Steam uses, but is not required to, and points to <APP-ID>.yaml for exactly how the launch should be processed. As one example, the Steam APP-ID for Cyberpunk 2077 is: 1091500, so 1091500.yaml inside of game-super-runtime's local storage would contain the instructions for how to launch Cyberpunk 2077.
Things that Game Super Runtime should support include environment variables, multiple application deployment inside of the same pressure vessel (ie. cheat engine plus game), all common linux overlays, precise control over proton edition and all control variables, precise prefix control, as well as prepared bash scripts given target variables. In short, a single starting executable that can nest and operate any possible version of a game startup sequence that anyone might want to use, and supports most or all of the features that are already common launch options or startup controls in games, as well as being able to launch other programs that might be required to run simultaneously by default without additional custom work required.
If a user launches a game through Steam with this tool (%command% parameter supplied), game-super-runtime should create a new yaml file with defaults. Those defaults may be nothing, in which case launching with game-super-runtime will be identical to launching the game for the end user. Or it might be a number of default launch commands, such as starting with gamemoderun and mangohud, or game-performance and gamescope, or whatever default set the user has.
Running `game-super-runtime <APP-ID> --edit` should pull up the yaml file in the default text editor, and if the yaml file doesn't exist create it under default conditions. `--edit-gui` should pull up a GUI interface, similar in style and substance to Steam Tinker Launch, which provides GUI users a way to edit the yaml file more friendly to them. It should be assumed that users only need a minimal level of technical fluency in order to use common and basic commands. Documentation should be included, and written in a manner suitable for an AI assistant first, technical user second.
Sanity checks of yaml input, clear errors to the end user with logs, clean exit, and a program which will not be something that needs to itself be debugged by the end user, especially when the action flow being deployed might be quite complex.

We are targeting a final product which can be both published to github and also potentially the AUR. Dependencies should be minimal, including only those elements that would absolutely exist on any system capable of running steam games. Rust is likely an ideal language, tooling is ready for it. Make it happen.
